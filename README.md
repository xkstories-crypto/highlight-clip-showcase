# 配信切り抜き 自動制作システム（個人開発・運用中）

ライブ配信（2〜6時間）から、テロップ入りの縦型ショート動画を自動で作るシステムです。
**設計・実装・機械学習・運用まで一人で担当**し、Discord bot として常時稼働させています。

> このリポジトリは実績紹介用です。本体（Python 約2.7万行・89ファイル）は非公開で、ここには主要な部品を単体で読める・動かせる形に切り出したコード（約1,200行）とテストを置いています。

## 何を作ったか

配信の検知から完成動画の受け渡しまでを、1本の処理としてつないでいます。人の作業は「候補から場面を選ぶ」ことだけです。

```mermaid
flowchart LR
    A[配信の検知<br/>yt-dlp] --> B[音声だけ取得]
    B --> C[山場の候補20件<br/>信号処理＋XGBoost]
    C --> D[人が選ぶ<br/>Discord bot]
    D --> E[範囲を決める<br/>Claude]
    E --> F[必要な区間だけ<br/>映像を部分取得]
    F --> G[中を削る<br/>学習モデル]
    G --> H[縦型化・テロップ<br/>ffmpeg]
    H --> I[受け渡し]
```

| 層 | 中身 |
|---|---|
| 常駐サービス | Discord bot、配信の巡回検知、ダウンロードの順番待ちと再試行、Firebase 経由の選別UI連携、エラー通知 |
| 解析 | 音量・話速・チャット密度などの特徴量、山場のランキングモデル、笑い声の検出、話者の識別 |
| 編集 | 文字起こし、範囲決め（LLM）、発言ごとの削り（学習モデル）、無音カット、縦型レイアウト、テロップ描画 |
| 運用 | タスクスケジューラによる自動復旧、配信者名簿（スプレッドシート）との同期、編集ソフト用データの書き出し |

## 成果（すべて実測）

- **選んでから完成動画まで約6分**（RTX 5090 で文字起こし・音声処理をGPU実行した場合。GPUの性能で変わります）
- **通信量を約20分の1に削減**：解析は音声だけで行い、映像は選ばれた区間だけを部分取得（7配信で 34GB → 1.5GB）
- **LLM の範囲決めで、必要な部分の取りこぼし 0件**（15本の検証。固定ルール時代は境界の一致度 IoU 0.6 が上限）
- **プロの削り方を学習したモデル**：人が付けた正解との一致度 AUC 0.645（数値だけ 0.593 から段階的に改善）
- **落ちても5分以内に自動復旧**、異常時は管理者へ即通知

## 設計で工夫したところ

### 1. 重い処理を後回しにして、通信と計算を減らす
最初は全編の映像を落としていましたが、山場を探すのに映像は要りません。
**音声だけで候補を絞り、人が選んだ区間の映像だけを部分取得**する流れに組み替えました。
部分取得は時刻のずれが起きやすい所なので、元配信の秒とファイル内の秒を必ず変換する関数を1か所に集め、取り違えると別の場面を切ってもエラーが出ない、という種類の不具合を防いでいます。

### 2. AI（LLM）は「判断」だけに使い、検査できる形で答えさせる
- 秒数を書かせず、**行番号を選ばせる**（LLM はもっともらしい嘘の秒数を出すため）
- 開始は3段階の候補を出させ、コード側で一番手前を採る。指示文で「広く取れ」と書くと終了まで伸びたので、選ぶ処理はコードに置いた
- 答えが範囲外・順序違いなら**黙って直さず例外**にし、呼び出し側で従来の範囲に戻して通知する
- 同じ入力でも答えが揺れるので、結果を保存して使い回す（同じ素材からは必ず同じ動画）

→ [`showcase/ai/range_decider.py`](showcase/ai/range_decider.py)

### 3. 正解データを自動で作り、学習モデルにする
削る発言の判定には、人手のラベル付けをせずに**公開されているプロの切り抜き動画を正解として使いました**。
切り抜き動画と元配信の音を1秒ずつ照合し（ログメル特徴の相関）、どこが使われてどこが削られたかを割り出して、数百本分の学習データを自動で作っています。

モデルは3種類の手がかりを XGBoost に重ねる構成です。

| 手がかり | AUC（人が付けた正解・封印したテスト） |
|---|---|
| 発言の長さ・話す速さ・前後の間など14個 | 0.593 |
| ＋声の大きさ・高さ（Praat）9個 | 0.627 |
| ＋配信の話し言葉で追加学習した文章モデル（ModernBERT） | **0.645** |

- 重ねるときは、その組を学習していないモデルの予測（out-of-fold）を使い、過学習を防ぐ
- 交差検証は**配信単位で分割**。行単位で分けると同じ配信の前後が漏れて、成績が12倍に水増しされることを実測で確認した
- 本番に移すときは、元の研究コードの数字（AUC 0.695 / 0.703 / 0.710）を**小数第3位まで再現できることを確認してから**切り替えた

→ [`showcase/ai/trim_model.py`](showcase/ai/trim_model.py) / [`trim_text.py`](showcase/ai/trim_text.py) / [`showcase/data/make_labels.py`](showcase/data/make_labels.py)

### 4. テロップは測ってから作る
プロの切り抜き動画 477本を見て、文字の大きさ・位置・縁取りを実測し、規則にしました。

- 形態素解析で文節を作り、**単語の途中で改行しない**。入らないときは改行より先に文字を縮める（3段階の探索）
- 文字の大きさは声の大きさと無関係（相関 +0.009）で、1行の字数で決まる（相関 −0.52）と分かったので、「大きく見せる＝短く割る」方針にした
- 字幕形式の縁取りは隣の字とくっつくと幅が乱れる。**距離変換で縁を塗り分ける描画**に作り替え、どこでも同じ幅にした

→ [`showcase/telop/layout.py`](showcase/telop/layout.py) / [`render.py`](showcase/telop/render.py)

### 5. 止まらない・黙らない運用
- 5分ごとの見張りで、落ちたら自動で起こす。ただし1時間に3回までにして、壊れたまま外部サービスを叩き続けない
- 外部サービスの一時的な失敗（5xx）は再試行し、自分のバグは1回目から通知する
- 失敗して「何もせず素通しする」箇所は、必ずログと通知を出す（気づかないまま品質が落ちるのを防ぐ）
- 大きな入れ替え（モデル・LLM・学習データ）は別の場所で作って検証し、成功してから切り替える。切り替えは設定1行で戻せるようにする

## 進め方

- **思い込みで直さず、比べて原因を特定する**。たとえば文字起こしが崩れる不具合は、処理を1段ずつ切り離した比較テストで、エンジンの違いが原因だと突き止めて解決した
- **数字は同じ物差しで比べる**。条件の甘い比較で「良くなった」と判断して、後で覆った経験から、比較は必ず同じデータ・同じ分割で行う
- 判断の理由と実測値は日付つきで記録し、後から検証できるようにしている
